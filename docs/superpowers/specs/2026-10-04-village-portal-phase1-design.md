# พอร์ทัลชุมชนน้ำท่วม — สเปกการออกแบบ เฟส 1

หมู่บ้านใน เคหะร่มเกล้า / คลองสองต้นนุ่น เขตลาดกระบัง กรุงเทพฯ (~300 หลังคาเรือน, กลุ่ม LINE ~300 คน)
วันที่: 2026-10-04 · สถานะ: ร่าง รอผู้ใช้ตรวจ

## 1. ปัญหาและเป้าหมาย

ปัจจุบันลูกบ้านถามในกลุ่ม LINE ซ้ำ ๆ ว่า "เส้นนี้ไปได้ไหม / รถเล็กไปได้ไหม / ตรงนั้นท่วมไหม / ซื้ออาหารได้ที่ไหน" และมีรูป/วิดีโอถูกส่งเข้ากลุ่มทุกวัน แต่ข้อมูลจมหายเมื่อไถขึ้นไปดู และไม่รู้ว่าอัปเดตเมื่อไหร่

**เป้าหมายเฟส 1:** เว็บพอร์ทัลบนมือถือที่ลูกบ้านเปิดแล้วเห็นทันที (1) สถานะถนนแต่ละช่วง (2) ระดับน้ำคลอง/ฝน/ประกาศเตือน (3) จุดซื้อเสบียงที่ยังเปิด และ (4) รายงานล่าสุดพร้อมรูป โดยทุกข้อมูลแสดงอายุ ลูกบ้านรายงานเองได้ทั้งหมดบนเว็บ

**นอกขอบเขตเฟส 1:** บอท/แจ้งเตือนเข้า LINE, เส้นทางสำเร็จรูปไปเมือง (เฟส 2), คำนวณเส้นทางอัตโนมัติ (เฟส 3), แอปติดตั้งแยก iOS/Android

## 2. ผู้ใช้

- **ลูกบ้าน/ผู้เยี่ยมชม:** ดูได้ทันที รายงานได้โดยไม่ต้องล็อกอิน ใส่ชื่อเล่น (ระบบจำเครื่อง) ไม่จำกัดเฉพาะคนในหมู่บ้าน
- **กรรมการ:** ล็อกอินแยก ยืนยัน/แก้ทับ/ลบรายงาน บล็อกเครื่อง ตั้งค่าอายุข้อมูลและเกณฑ์ระดับน้ำ จัดการช่วงถนน ขีดวัดระดับ และจุดเสบียง

## 3. ฟีเจอร์เฟส 1

1. **หน้าแรก** — แถบสรุปบนสุด (ระดับน้ำเกจหลัก + แนวโน้ม, ประกาศเตือนกรมอุตุฯ, สถานะกำแพง/ระบายน้ำที่กรรมการอัปเดต), ตามด้วยฟีดรายงานล่าสุด (เรียงตามเวลา มีรูป ผู้ส่ง ป้ายยืนยัน อายุ)
2. **แผนที่ช่วงถนน** — แต่ละช่วงสี 5 สถานะ: แห้ง / รถเล็กไปได้ / รถยกสูงเท่านั้น / ผ่านไม่ได้ / **ไม่ทราบ**; แตะช่วงเพื่อดูรายงานและส่งรายงานใหม่
3. **รายงาน** (ดู §4) — ถนน, ระดับน้ำ (ตามขีดวัด), จุดเสบียง, ข้อความทั่วไป
4. **จุดเสบียง** — รายการร้านอาหาร/ตลาด/ร้านสะดวกซื้อ/ปั๊ม/โรงพยาบาลใกล้หมู่บ้าน พร้อมสถานะที่ลูกบ้านรายงาน (เปิด / ปิด / ของหมด / เข้าถึงไม่ได้) และอายุข้อมูล; ข้อมูลตั้งต้นจากการเก็บครั้งเดียว (OSM Overpass + ตรวจมือ) ไม่ใช้ Google Places (เก็บแคชไม่ได้ตามเงื่อนไข)
5. **ข้อมูลหน่วยงาน** (ดู §5)
6. **กระดานกรรมการ** — ยืนยัน/แก้ทับ/ลบรายงาน, บล็อกเครื่อง, จัดการช่วงถนน/ขีดวัด/จุดเสบียง, ตั้งค่าอายุและเกณฑ์

## 4. กติการายงานและความปลอดภัยของข้อมูล

ความผิดพลาดที่ร้ายแรงที่สุดคือแสดง "รถเล็กไปได้" ทั้งที่ไปไม่ได้ กติกาต่อไปนี้เป็นข้อบังคับของระบบ ไม่ใช่ตัวเลือก

| รายงาน | หลักฐาน |
|---|---|
| ระดับน้ำ (คลอง กำแพง ถนนในหมู่บ้าน) | **บังคับ** รูปหรือวิดีโอ |
| ถนน แห้ง / รถเล็กไปได้ / รถยกสูงเท่านั้น | **บังคับ** |
| ถนน ผ่านไม่ได้ | ไม่บังคับ |
| จุดเสบียง, ข้อความทั่วไป | ไม่บังคับ |

- **ระดับน้ำใช้ขีดวัด:** กรรมการกำหนด 3–5 จุด ตีขีด/ติดสติกเกอร์ ลูกบ้านเลือกขีดที่น้ำถึงและถ่ายให้เห็นขีด
- **หลักฐานต้องถ่ายใหม่** ในหน้าแอป (ไม่เลือกจากคลังภาพ) เก็บเวลาและพิกัดตอนส่ง; พิกัดห่างจากช่วงถนน/จุดมากเกินกำหนด → ติดป้าย "ตำแหน่งไม่ตรง" และไม่มีผลต่อสถานะจนกว่ากรรมการยืนยัน
- **ป้าย:** "มีรูปยืนยัน", "มีผู้อื่นยืนยัน (n คน)", "กรรมการยืนยัน" (น้ำหนักสูงสุด)
- **รายงานขัดแย้ง:** แสดงสถานะที่ **แย่กว่า** พร้อมข้อความ "มีรายงานขัดแย้ง" จนกว่ากรรมการแก้ทับ
- **อายุข้อมูล (ค่าตั้งต้น กรรมการปรับได้):** สถานะถนนหมดอายุเป็น "ไม่ทราบ" หลัง 3 ชม.; ระดับน้ำหลัง 2 ชม.; จุดเสบียงหลัง 12 ชม. — ไม่มีสถานะใดค้างเป็นสีเขียวเมื่อหมดอายุ
- **ทุกข้อมูลแสดงอายุ** ("อัปเดต 20 นาทีที่แล้ว") และข้อมูลเก่าจากหน่วยงานไม่ถูกนำมาแสดงเป็นสถานะปัจจุบัน
- **ข้อความกำกับถาวร:** "ข้อมูลชุมชน ไม่ใช่ประกาศเตือนภัยทางการ"
- **ควบคุมการใช้งาน:** ชื่อเล่น + จำเครื่อง, จำกัดความถี่ต่อเครื่อง, กรรมการลบ/บล็อกได้
- **รูป/วิดีโอ:** ย่อบนเครื่องก่อนอัปโหลด; วิดีโอ ≤ ~15 วินาที; ลบอัตโนมัติหลัง 30 วัน (ค่าตั้งต้น) เพราะอาจมีใบหน้า/ป้ายทะเบียน/เลขที่บ้าน (PDPA); มีประกาศความเป็นส่วนตัวภาษาไทยและช่องทางขอลบ; ผู้ควบคุมข้อมูลคือกรรมการหมู่บ้าน (ปรึกษาผู้รู้ด้านกฎหมายก่อนเปิดใช้จริง)

## 5. ข้อมูลหน่วยงาน

ตัวดึงข้อมูลทุก ~10 นาที เก็บประวัติลงฐานข้อมูลของเรา (คำนวณแนวโน้ม "กำลังขึ้น/ลง" เอง)

| แหล่ง | ใช้ทำอะไร | หมายเหตุ (ตรวจแล้ว 2026-10-04) |
|---|---|---|
| กทม. สำนักการระบายน้ำ weather.bangkok.go.th | ระดับน้ำคลอง, ฝนรายสถานี | **ไม่มี API ทางการ** ใช้ JSON ที่อยู่หลังหน้าเว็บ อาจเปลี่ยนโดยไม่แจ้ง; ไม่พบเงื่อนไขการใช้ข้อมูล |
| ThaiWater (สสน.) | คลองลำปลาทิว ลาดกระบัง | ไม่มีเอกสาร API |
| กรมอุตุฯ data.tmd.go.th | ประกาศเตือน, พยากรณ์รายชั่วโมงตามพิกัด | ลงทะเบียนฟรี |
| iTIC/Longdo event feed | เหตุน้ำท่วมถนนแบบสด | CC-BY 4.0 ต้องให้เครดิต |
| data.bangkok.go.th | จุดเสี่ยง/คันกั้นน้ำ (ชั้นพื้นฐาน) | อัปเดตรายปี |

**เกจหลัก:** WL.STN.02 คลองสองต้นนุ่น ซ.ร่มเกล้า 20 · เกจประกอบ: WL.STN.01, WL.STN.03 (คลองสองต้นนุ่น), WL.LBK.02 (คลองลาดบัวขาว), ปตร.คลองประเวศฯ-ลาดกระบัง; ฝน: RF.MBR.03, RF.LKB.02, RF.SPS.01
**เซ็นเซอร์น้ำท่วมถนนของ กทม. ไม่มีที่ ถ.ร่มเกล้า/เคหะร่มเกล้า** → ข้อมูลถนนส่วนนี้มาจากลูกบ้านเท่านั้น

**เกณฑ์เตือน:** ช่วงแรกแสดงค่าดิบ + แนวโน้ม ไม่ใส่สี เพราะฟิลด์ warning/critical ของ กทม. อ่านเกินวิกฤตที่ทุกสถานีใกล้หมู่บ้านพร้อมกัน (น่าจะเทียบกับค่าที่อ่านโดยตรงไม่ได้) กรรมการตั้งเกณฑ์ "เฝ้าระวัง/อันตราย" เองโดยเทียบกับขีดวัดที่กำแพง
**ข้อมูลเก่า:** ตรวจ timestamp รายสถานี (บางสถานีเก่าหลายวัน) สถานีเก่าเกินกำหนดแสดง "ข้อมูลเก่า" ไม่นำมาใช้
**ล่ม:** แสดง "ไม่มีข้อมูลล่าสุด" พร้อมเวลาล่าสุดที่ได้ ไม่แสดงค่าเก่าเป็นค่าปัจจุบัน

**ตรวจไม่ได้:** Traffy Fondue (เชื่อมต่อไม่ติด), กรมชลประทาน, ปภ. (ไม่พบ feed; แจ้งเตือนผ่านแอปทางรัฐถูกระงับ 3 ต.ค. 2026) — ไม่ใช้ในเฟส 1

## 6. สถาปัตยกรรม

- **หน้าเว็บ:** PWA ภาษาไทย mobile-first โฮสต์บน Vercel; แผนที่ MapLibre + OpenFreeMap (ฟรี ไม่จำกัดจำนวนครั้งเปิด); เฟรมเวิร์กเลือกในแผนการสร้าง
- **Supabase:** Postgres (ช่วงถนน, ขีดวัด, จุดเสบียง, รายงาน, ค่าจากหน่วยงาน, ผู้ใช้/เครื่อง), Storage (รูป/วิดีโอ), Auth (กรรมการ), งานลบรูปตามอายุ
- **ตัวดึงข้อมูลหน่วยงาน:** งานตั้งเวลา ที่ตั้งขึ้นกับผลทดสอบ (§8)
- **สถานะคำนวณฝั่งเซิร์ฟเวอร์** จากรายงานที่ยังไม่หมดอายุ + กติกา §4 เพื่อให้ทุกไคลเอนต์เห็นตรงกัน
- **ออฟไลน์/เน็ตแย่:** รายงานที่ส่งไม่สำเร็จเก็บในเครื่องและส่งซ้ำ พร้อมแจ้ง "ยังไม่ได้ส่ง"; หน้าแรกและสถานะล่าสุดที่แคชไว้เปิดดูได้พร้อมป้ายอายุ
- **ค่าใช้จ่ายโดยประมาณ:** เกือบ 0 บาท; โดเมน ~400 บาท/ปี (ไม่บังคับ); VPS ในไทย 100–300 บาท/เดือน เฉพาะกรณี กทม. บล็อกคลาวด์ — **ยังไม่ได้ตรวจโควตาฟรี/เงื่อนไขของ Supabase และ Vercel** (ที่เก็บรูป, การหยุดโปรเจกต์เมื่อไม่มีคนใช้) ต้องตรวจก่อนสร้าง

## 7. การทดสอบ

- ทดสอบอัตโนมัติกับกติกาที่ผิดแล้วอันตราย: หมดอายุ → "ไม่ทราบ"; ขัดแย้ง → แสดงที่แย่กว่า; ข้อมูลหน่วยงานเก่าไม่แสดงเป็นปัจจุบัน; รายงาน "ไปได้" ที่ไม่มีหลักฐานถูกปฏิเสธ; พิกัดไม่ตรง → ไม่มีผลต่อสถานะ
- ทดสอบบนมือถือจริง iOS + Android รวมถึงเปิดจากลิงก์ในกลุ่ม LINE (เบราว์เซอร์ของ LINE)
- ซ้อมเหตุการณ์จำลองกับกรรมการ 1 รอบก่อนปล่อยใช้

## 8. ความเสี่ยงที่ต้องทดสอบก่อนสร้าง

1. **ดึงข้อมูล กทม. จากโฮสต์ที่จะใช้จริง** — มีรายงานจากโครงการอื่นว่าถูก 403 จาก IP ต่างประเทศ/GitHub Actions; ผลกำหนดว่าตัวดึงข้อมูลต้องอยู่ในไทยหรือไม่
2. **กล้อง (ถ่ายใหม่เท่านั้น) และตำแหน่งบน iOS/Android ในเบราว์เซอร์ LINE** — การบังคับ "ไม่เลือกจากคลังภาพ" ต้องทำงานจริงทั้งสองระบบ มิฉะนั้นกติกา §4 ต้องปรับ
3. **โควตา/เงื่อนไข Supabase และ Vercel** สำหรับรูป/วิดีโอและการใช้งานต่อเนื่อง

## 9. ข้อมูลตั้งต้นที่ต้องเก็บ (ทำร่วมกับกรรมการ)

- ช่วงถนนหลักในและรอบหมู่บ้าน (วาดบนแผนที่, ตรวจ/แก้ถนนใน OSM ถ้าจำเป็น)
- จุดขีดวัดระดับ 3–5 จุด
- จุดเสบียง ~15–25 จุด
- เกณฑ์เฝ้าระวัง/อันตรายของเกจ WL.STN.02 (หลังเทียบกับขีดวัดในช่วงฝน)

## 10. เฟสถัดไป (ยังไม่อยู่ในสเปกนี้)

- **เฟส 2:** เส้นทางสำเร็จรูป 10–20 เส้นไปเมือง/ถนนหลัก/จุดเสบียง แยกรถเล็ก/รถยกสูง + ปุ่มเปิด Google Maps (จุดแวะบนมือถือ ≤ 3 จุด; Google อาจพาอ้อมเข้าถนนท่วม จึงแสดงเส้นทางในแอปเสมอ)
- **เฟส 3:** คำนวณเส้นทางอัตโนมัติ (OpenRouteService `avoid_polygons` หรือ Valhalla — ต้องยืนยันโควตาก่อน)
- **ภายหลัง:** บอท LINE/แจ้งเตือนเข้ากลุ่ม — การส่งเข้ากลุ่มคิดโควตาตามจำนวนสมาชิก (300 คน = 300 ข้อความต่อครั้ง; แพ็กเกจฟรี 300 ข้อความ/เดือน, Basic 1,280 บาท + VAT ได้ 15,000 ข้อความ ยืนยันราคาใน OA Manager ก่อน)
- ดูโครงการที่ทำใกล้เคียงก่อนเริ่ม: floodboard.org, github.com/kmusicman/bangkok-flood-watch
